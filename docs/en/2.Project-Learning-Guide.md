# mini-claw Project Learning Guide

## 1. Project Introduction

**mini-claw** is a streamlined AI Agent runtime platform, referencing the design concepts of OpenClaw, Nanobot, CoPaw and other projects. It is a simplified, mini version of OpenClaw. The project is built on the [agentscope-java](https://github.com/alibaba/agentscope-java) framework, with about 4000 lines of total code and about 1000 lines of core code, making it very suitable as an introductory project for learning AI Agent. Before learning, it is strongly recommended to read [1.Agent-Basic-Concepts.md](1.Agent-Basic-Concepts.md).

**Target Audience:**

- Those who want to understand the core principles of OpenClaw and similar projects but don't know where to start
- Those who need to learn how to develop Agent applications based on agentscope-java
- Those who want to quickly understand the architecture design and key modules of AI Agent applications

### Core Features

| Feature | Description |
|:--------|:------------|
| **Multi-channel Support** | Standard input/output, Web API (HTTP + SSE), Feishu (Lark) bot, one-click switching |
| **Tool Calling** | Built-in file read/write, search, shell execution, date tools, supports custom Skill extension |
| **Scheduled Tasks** | Supports periodic tasks, Cron expressions, one-time delayed tasks, based on Quartz scheduler |
| **Session Persistence** | Session storage and recovery based on JsonSession, supports resuming conversations |
| **Multi-model Support** | Supports OpenAI, Anthropic and other mainstream LLM models, flexible configuration |

## 3. Overall Architecture Design

### Architecture Overview

mini-claw adopts a layered architecture design, from top to bottom:

```
┌─────────────────────────────────────────────────────────┐
│                      User Layer                          │
│       CLI (Command Line) | Web Frontend | Feishu Client │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                    Channel Layer                         │
│   StdChannel | WebChannel (HTTP+SSE) | FeishuChannel    │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                      Core Layer                          │
│         AgentMessageQueue | ChannelManager              │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                     Agent Layer                          │
│  AgentRunner | ReActAgent | Memory | JsonSession        │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                   Tool Layer (Toolkit)                   │
│  FileIO | FileSearch | Shell | Date | Cron              │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                     Model Layer                          │
│            OpenAI API | Anthropic API                   │
└─────────────────────────────────────────────────────────┘
```

### Core Module Details

#### 1. Channel Layer

**Responsibility**: Unify message processing flow for different access methods

The channel layer is the entry point of mini-claw, responsible for converting messages from different sources into a standard format that the Agent can process.

```java
// Channel base class
public abstract class BaseChannel {
    protected ChannelType channelType;
    protected AgentMessageQueue agentMessageQueue;
    
    // Unified entry for processing messages
    public void process(String userId, String sessionId, String text);
    
    // Permission check
    public boolean isAllowed(String userId);
    
    // Send response
    public abstract void send(AgentResponse response);
}
```

**Three Channel Implementations**:

| Channel | Description | Use Case |
|:--------|:------------|:---------|
| **StdChannel** | Standard input/output, simplest command line interaction | Local development, debugging and testing |
| **WebChannel** | HTTP REST API + SSE push | Web applications, mobile integration |
| **FeishuChannel** | Feishu (Lark) bot, supports private chat and group mention | Enterprise internal tools, instant messaging |

#### 2. Core Layer

**Responsibility**: Message queue management and channel orchestration

The core layer contains two key components:

- **AgentMessageQueue**: Message queue, responsible for receiving requests from various channels and distributing them to AgentRunner in order
- **ChannelManager**: Channel manager, responsible for starting and stopping all channels, and maintaining the relationship between channels and the message queue

```java
// Message flow
User → Channel → AgentMessageQueue → AgentRunner → Agent
                                                    ↓
User ← Channel ← AgentMessageQueue ← AgentRunner ← Agent
```

#### 3. Agent Layer

**Responsibility**: Agent running, reasoning and session management

The Agent layer is the core business logic layer, containing:

- **AgentRunner**: Agent runner, takes requests from the message queue, creates or restores Agent instances
- **ReActAgent**: Reasoning and execution Agent, performs iterative reasoning based on ReAct (Reasoning + Acting) mode
- **AutoContextMemory**: Auto context memory, manages conversation history
- **JsonSession**: Session persistence, saves session state to JSON files

**Running Process**:

```
1. AgentRunner takes request from queue
2. Load corresponding session's JsonSession (if exists)
3. Create or restore Agent instance
4. Agent performs reasoning-execution loop:
   a. Call LLM model to generate response
   b. If tool call needed, execute tool and continue reasoning
   c. Until final answer is generated
5. Save session state
6. Return response to channel
```

#### 4. Tool Layer

**Responsibility**: Provide various capability extensions

The tool layer provides a series of built-in tools, Agent can complete specific tasks through tool calling:

| Tool Class | Function | Included Tools |
|:-----------|:---------|:---------------|
| **FileIOTools** | File operations | readFile, writeFile, editFile, appendFile |
| **FileSearchTools** | File search | searchFiles, listFiles |
| **ShellTools** | Command execution | executeShell |
| **DateTools** | Date and time | currentDate |
| **CronTools** | Scheduled tasks | every, cron, at, delay, cancel |

#### 5. Scheduler Layer

**Responsibility**: Scheduled task management

The scheduler layer is based on Quartz implementation, supporting:

- **Periodic Tasks**: Execute at fixed periods (e.g., every 5 minutes)
- **Cron Tasks**: Define execution time using Cron expressions
- **One-time Tasks**: Execute at specified time or after delay

```java
// Scheduled task examples
// Execute every 10 seconds
every_seconds(10, "Check system status")

// Use Cron expression (every day at 9:00)
cron_expr("0 0 9 * * ?", "Send daily report")

// Execute once after 5 minutes
delay_seconds(300, "Remind me to attend meeting")
```

#### 6. Model Layer

**Responsibility**: Interact with LLM models

The model layer encapsulates interaction logic with different LLM providers, supporting:

- **OpenAI API**: GPT-4, GPT-4o, GPT-3.5-turbo, etc.
- **Anthropic API**: Claude 3.5 Sonnet, Claude 3 Opus, etc.
- **OpenAI Compatible API**: Supports other services compatible with OpenAI interface

## 4. Message Processing Flow

### Complete Message Flow Process

```
┌──────────┐
│   User   │
└────┬─────┘
     │ 1. Send message
     ↓
┌──────────────────┐
│    Channel       │ ← 2. Permission check (allowFrom)
│  (Channel Layer) │
└────┬─────────────┘
     │ 3. Create AgentRequest
     ↓
┌──────────────────┐
│ AgentMessageQueue│ ← 4. Put into message queue
│  (Message Queue) │
└────┬─────────────┘
     │ 5. takeRequest()
     ↓
┌──────────────────┐
│  AgentRunner     │ ← 6. Load session JsonSession
│    (Runner)      │ ← 7. Create/restore Agent
└────┬─────────────┘
     │
     ↓
┌──────────────────┐
│   ReActAgent     │ ← 8. Reasoning-execution loop
│    (Agent)       │
└────┬─────────────┘
     │ 9. Call LLM model
     ↓
┌──────────────────┐
│   Model (LLM)    │ ← 10. Return response (may contain tool calls)
│  (Model Layer)   │
└────┬─────────────┘
     │ 11. If tool call needed
     ↓
┌──────────────────┐
│   Tools/Skills   │ ← 12. Execute tool
│   (Tool Layer)   │
└────┬─────────────┘
     │ 13. Tool result returns to Agent
     ↓
┌──────────────────┐
│   ReActAgent     │ ← 14. Continue reasoning (loop steps 8-13)
└────┬─────────────┘
     │ 15. Final response
     ↓
┌──────────────────┐
│  AgentRunner     │ ← 16. Save session
└────┬─────────────┘
     │ 17. Return AgentResponse
     ↓
┌──────────────────┐
│ AgentMessageQueue│ ← 18. Response put back into queue
└────┬─────────────┘
     │ 19. Distribute to corresponding channel
     ↓
┌──────────────────┐
│    Channel       │ ← 20. Send to user
└────┬─────────────┘
     ↓
┌──────────┐
│   User   │
└──────────┘
```

### Session Persistence Mechanism

mini-claw uses JsonSession to implement session persistence:

1. **Session Isolation**: Each user+session has independent context
2. **Auto Save**: Agent automatically saves session state after each response
3. **Resume Conversation**: Automatically loads historical session when user sends next message
4. **Cross-channel Sharing**: Same session shares state across different channels

## 6. Key Technical Points

### 1. Channel Extension Mechanism

mini-claw provides a flexible channel extension mechanism, adding a new channel only requires:

```java
// 1. Extend BaseChannel
public class MyChannel extends BaseChannel {
    
    // 2. Implement start logic
    @Override
    public void start() {
        // Initialize channel
    }
    
    // 3. Implement stop logic
    @Override
    public void stop() {
        // Clean up resources
    }
    
    // 4. Implement message sending logic
    @Override
    public void send(AgentResponse response) {
        // Send response to user
    }
}

// 5. Add config class
public class MyChannelConfig extends BaseChannelConfig {
    // Channel specific config
}
```

### 2. Tool Registration Mechanism

Tools are managed uniformly through ToolManager:

```java
// Register tool
toolManager.registerTool(tool);

// Agent can call by tool name
toolManager.executeTool(toolName, arguments);
```

### 3. Scheduled Task Scheduling

Based on Quartz implementation, supports multiple trigger methods:

```java
// Periodic task (every 10 seconds)
schedulerService.scheduleEvery(10, TimeUnit.SECONDS, task);

// Cron expression (every day at 9:00)
schedulerService.scheduleCron("0 0 9 * * ?", task);

// Delayed task (after 5 minutes)
schedulerService.scheduleDelay(5, TimeUnit.MINUTES, task);
```

## 7. Learning Suggestions

### Recommended Learning Path

1. **Phase 1: Understand Concepts**
   - Learn Agent basic concepts, refer to [Agent Framework Documentation](./docs/Agent-Framework-Documentation.md)
   - Familiarize with agentscope-java framework
   
2. **Phase 2: Run the Project**
   - Configure development environment (Java 25+, Maven)
   - Configure config.json file
   - Run StdChannel to experience basic functionality
   - Try WebChannel and Feishu channel

3. **Phase 3: Read Core Code**
   - **Beginner**: `Main.java` → `ConfigLoader.java` → `AgentRunner.java`
   - **Intermediate**: `BaseChannel.java` → `AgentMessageQueue.java` → Various channel implementations
   - **Advanced**: `tool/` directory → `cron/` directory → `skill/` directory

4. **Phase 4: Practice Extension**
   - Add custom tools
   - Extend new channels
   - Implement Skill extension
   - Customize Agent

### Recommended Reading Order for Key Files

```
1. Main.java (Entry)
   ↓
2. ConfigLoader.java, Config.java (Config loading)
   ↓
3. ChannelManager.java (Channel management)
   ↓
4. BaseChannel.java, StdChannel.java (Channel base class and simple implementation)
   ↓
5. AgentMessageQueue.java (Message queue)
   ↓
6. AgentRunner.java (Agent runner)
   ↓
7. tool/*/ (Tool implementations)
   ↓
8. cron/schedule/SchedulerService.java (Scheduler service)
```
