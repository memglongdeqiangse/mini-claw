# mini-claw 与同类 Bot 项目的差距分析

> 分析对象：`memglongdeqiangse/mini-claw`（`main`，提交 `71b8ae9`）
> 对比基线：OpenClaw、QwenPaw（原 CoPaw）、nanobot，以及个人助理/客服类 Bot 的常见能力
> 方法：阅读本仓库源码与各项目公开 README，做能力面的静态对比；不是性能压测，也不评价模型本身
> 日期：2026-11-03

## 结论

mini-claw 已经跑通“渠道 → 消息队列 → ReAct Agent → 工具 → 会话”的主链路，作为约 4000 行的学习项目结构清晰；它与成熟 Bot 的差距不在“能不能调用模型”，而在**安全边界、并发与故障隔离、IM 交互、生态与运维**。其中安全与稳定性是投入产出比最高的补齐方向。

下面按优先级列出差距。部分项是学习项目的合理省略，是否补齐取决于目标场景；但如果要把它作为“别人也能用的 Bot”部署，P0/P1 基本是前置条件。

## 对比基线

| 维度 | OpenClaw | QwenPaw（原 CoPaw） | nanobot | mini-claw |
|:--|:--|:--|:--|:--|
| 定位 | 个人助理网关，本地/团队 | 个人助理平台，本地/云 | 轻量个人 Agent 框架 | 学习型迷你实现 |
| IM 渠道 | Discord、iMessage、Slack、Teams、Telegram、WhatsApp 等 20+，含原生 App | 钉钉、飞书、微信、Discord、Telegram、iMessage、QQ 等，含 Console/TUI/桌面端 | WebUI/TUI，Telegram、Discord、Slack、微信、邮件、Mattermost、Linear、飞书、Teams | stdio、Web、飞书（仅文本） |
| 多模态/文件 | 语音、Canvas、相机、屏幕等设备能力 | 文件工作区、文档处理、浏览器、computer-use | PDF/Word/Excel/PPT、图像生成 | 纯文本；无文件/图片输入 |
| 记忆 | 状态、记忆、凭据保存在本机 | 三层记忆 + ReMe 个人知识库 | Dream 长期记忆 | JSON 会话 + 上下文截断 |
| 工具/生态 | 插件 SDK、ClawHub 技能市场 | Skills/Plugins/MCP/市场 | MCP、技能、多 Agent | 9 个内置工具 + 文件系统 Skills |
| 安全 | 陌生私聊配对、可配置 sandbox、安全指南 | 内核级 sandbox、Tool Guard、File Guard、Skill Scanner、访问策略 | 安全配置 | 仅 `allowFrom`；Shell/文件无沙箱 |
| 并发 | 网关、多会话 | 多 Agent、并行 | 多 Agent | 全局单线程 |
| 模型 | 可插拔（Claude、Codex、本地模型） | 本地模型 + 14+ 云厂商 | OpenAI 兼容、本地模型、fallback | OpenAI/Anthropic 兼容，单 Provider |
| 部署/运维 | Docker、Nix、桌面/原生 | pip、Docker、桌面、云 | pip、Docker、云、WebUI | Maven + JDK 25 |
| 工程化 | 大型社区与持续发版 | 持续发版 | CI/测试徽章 | 无测试、无 CI、无容器 |

> 对比信息来自各项目 README（2026-11-03）。OpenClaw/QwenPaw/nanobot 都是数万到数十万 star、持续发版的成熟项目；mini-claw 是学习项目，功能数量上的差距是正常的，表格用于定位“还缺哪一层”，不是要求逐项对齐。

## P0 安全与权限

### 1. Shell 可以在宿主机执行任意命令，且没有审批/沙箱

[ShellTools.java:170-183](../../src/main/java/com/miniclaw/tool/shell/ShellTools.java#L170-L183) 直接用 `/bin/sh -c` 执行模型给出的命令，`workspace` 只是工作目录；没有命令白名单、人工审批、容器或系统级隔离。与此同时，飞书渠道在 `allowFrom` 为空时默认允许所有发送者（[FeishuChannel.java:131-137](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L131-L137)）。

这意味着：任何能给机器人发消息的人（群聊里 @ 一下即可）都能以进程用户身份执行命令、读取密钥、修改文件。对比之下，OpenClaw 默认对陌生私聊做配对，并支持 sandbox；QwenPaw 提供内核级 sandbox、Tool Guard、File Guard、Access Policy。

这是当前最需要优先处理的问题。

### 2. 文件工具可以越出 workspace

[FileIOTools.java:206-213](../../src/main/java/com/miniclaw/tool/file/FileIOTools.java#L206-L213) 对绝对路径原样返回，相对路径也没有做 `..` 规范化；[FileSearchTools.java:342-349](../../src/main/java/com/miniclaw/tool/file/FileSearchTools.java#L342-L349) 同样如此。读文件、写文件、grep/glob 都可以访问进程有权限的任意路径，例如 `~/.ssh`、`/etc`、其他项目目录。

### 3. Web 渠道没有鉴权

[WebChannelHandler.java:88-116](../../src/main/java/com/miniclaw/channel/web/WebChannelHandler.java#L88-L116) 从请求体里取 `userId`/`sessionId`，没有 token、登录态或签名校验；`allowFrom` 为空时 `isAllowed` 直接放行。SSE 的 `/api/sse/{sessionId}` 也只按 sessionId 订阅，没有身份校验（[WebChannelHandler.java:180-186](../../src/main/java/com/miniclaw/channel/web/WebChannelHandler.java#L180-L186)）。

`sessionId` 还参与会话目录拼接：`workspace + "/sessions/" + sessionId`（[AgentRunner.java:126](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L126)）。如果 Web 客户端传入 `../` 之类的值，存在路径穿越风险；知道或猜到 sessionId 的人也能订阅别人的回复。

另外，`WebChannelConfig.enableCors`（[WebChannelConfig.java:31](../../src/main/java/com/miniclaw/channel/config/WebChannelConfig.java#L31)）并没有被使用——不是“CORS 已开启”，而是这个配置项没生效。

### 4. 密钥与日志没有脱敏

[LoggingHook.java:19-36](../../src/main/java/com/miniclaw/hook/LoggingHook.java#L19-L36) 会打印完整 prompt、模型返回和工具入参；配置固定在 `~/.mini-claw/config.json`（[ConfigLoader.java:32-39](../../src/main/java/com/miniclaw/config/ConfigLoader.java#L32-L39)），`apiKey`、飞书 `appSecret` 都是明文。日志或配置一旦泄露，密钥就跟着泄露。

### 5. 群聊上下文与提示注入

飞书群聊用 `chatId` 作为 sessionId（[FeishuChannel.java:124](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L124)），同一群所有成员共享一份会话，没有 per-user 隔离。文件、网页、群消息都可能携带提示注入，而工具调用没有审批或确认环节；对“个人助理”来说，这是权限模型缺失，而不只是模型问题。

## P1 并发、可靠性与定时任务

### 1. 全局单线程，一个慢请求阻塞所有人

[AgentRunner.java:85-90](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L85-L90) 是一个单循环：`takeRequest()` 取一条，`processRequest()` 同步处理完再取下一条；`mainAgent.call(input).block()`（[AgentRunner.java:138](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L138)）会一直等到模型返回。一个长 Shell、慢模型或挂起的网络请求会占住唯一的执行线程，其他用户的消息只能排队。请求队列还是无界的 `LinkedBlockingQueue`（[AgentMessageQueue.java:25-26](../../src/main/java/com/miniclaw/bus/AgentMessageQueue.java#L25-L26)），没有背压或限流。

### 2. 一个请求异常会结束主循环

`processRequest` 没有 per-request 的 try/catch；异常会冒泡到 `run()` 的 catch（[AgentRunner.java:95-100](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L95-L100)），循环退出，`finally` 停掉渠道。也就是说，一条格式异常的消息、一次模型错误，就可能让整个 Bot 停止服务，而且用户收不到错误提示。`block()` 也没有超时和取消机制。

### 3. 飞书链路存在多个可用性缺陷

- 只发送最终文本（[FeishuChannel.java:140-151](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L140-L151)），没有流式输出、工具进度或 typing 提示；长文本不分片，发送失败不重试（[FeishuChannel.java:162-188](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L162-L188)）。
- 权限拒绝和解析失败的提示把 `p2p`/`group` 当作 `receive_id_type`（[FeishuChannel.java:84](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L84)、[94](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L94)），实际 API 不接受这两个值，提示发不出去。
- 非文本消息直接被拒绝（[FeishuChannel.java:118-121](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L118-L121)）；群聊的 @ 判断在消息类型检查之前（[FeishuChannel.java:99-116](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L99-L116)），带 @ 的图片消息 `text` 为 null，后续 `text.trim()`（[BaseChannel.java:58](../../src/main/java/com/miniclaw/channel/BaseChannel.java#L58)）会 NPE；`botOpenId` 未配置时，群聊甚至不校验是否 @。
- 没有消息去重/幂等；WebSocket 重投时可能重复执行工具。
- `stop()` 没有真正断开连接（[FeishuChannel.java:204-208](../../src/main/java/com/miniclaw/channel/feishu/FeishuChannel.java#L204-L208)）。

### 4. 定时任务不具备生产可用性

- `QuartzAgentScheduler.builder().autoStart(true).build()`（[SchedulerService.java:57](../../src/main/java/com/miniclaw/cron/schedule/service/SchedulerService.java#L57)）使用默认 `StdSchedulerFactory`；项目没有 `quartz.properties` 或 JobStore 配置，默认是 RAMJobStore，重启后任务丢失。
- 定时任务构造的 `RuntimeAgentConfig` 只传了空 `Toolkit`（[SchedulerService.java:131-132](../../src/main/java/com/miniclaw/cron/schedule/service/SchedulerService.java#L131-L132)），没有注册文件、Shell、Cron 工具，实际执行时能力远低于主 Agent。
- `CronTools.cron()` 先返回 “submitted”（[CornTools.java:50-51](../../src/main/java/com/miniclaw/tool/cron/CornTools.java#L50-L51)），校验错误不会回传给模型。
- `delaySeconds` 是原始 `int`，默认 0，`>= 0` 分支（[SchedulerService.java:121-125](../../src/main/java/com/miniclaw/cron/schedule/service/SchedulerService.java#L121-L125)）永远命中；即使什么都没配，也会创建一个立即执行的任务，而不是报错。
- `removeJob` 不校验任务归属（[SchedulerService.java:179-190](../../src/main/java/com/miniclaw/cron/schedule/service/SchedulerService.java#L179-L190)），知道 jobId 就能删别人的任务。
- `shutdown()` 是空实现（[SchedulerService.java:195-197](../../src/main/java/com/miniclaw/cron/schedule/service/SchedulerService.java#L195-L197)）。

## P2 交互与渠道

### 1. 飞书只支持纯文本

没有图片、文件、语音、富文本卡片或按钮；`markdownEnabled` 配置没有被使用，消息仍按 `MessageText` 纯文本发送。`denyMessage`、`botPrefix`、`filterToolMessages`、`filterThinking` 也没有真正生效：这些字段在配置/基类中被赋值后，没有实际消费方。

### 2. 缺少过程反馈

ReAct 多轮工具调用期间，用户看不到任何进展，只能等最终消息；长任务很容易被误认为“卡住了”，也容易引发反复追问。飞书端也没有线程回复、卡片更新或按钮交互。

### 3. 命令是占位实现

`/help`、`/compact`、`/new`、`/clear` 在 [CommandType.java:13-24](../../src/main/java/com/miniclaw/command/CommandType.java#L13-L24) 里只返回固定字符串，没有会话重置、上下文压缩或帮助信息。

### 4. Web 端的“流式”只是最终消息

`/api/chat` 只入队并立即返回，真正结果靠 SSE（[WebChannelHandler.java:88-131](../../src/main/java/com/miniclaw/channel/web/WebChannelHandler.java#L88-L131)）；不订阅 SSE 就没有回复。`/api/chat/stream` 先入队再注册 SSE（[WebChannelHandler.java:137-174](../../src/main/java/com/miniclaw/channel/web/WebChannelHandler.java#L137-L174)），存在竞态；SSE 发送的也只是最终消息（[WebChannel.java:65-95](../../src/main/java/com/miniclaw/channel/web/WebChannel.java#L65-L95)），不是 token 级流式。

### 5. 渠道覆盖少

当前只有 stdio、Web、飞书。对比项目分别覆盖 20+、7+、9+ 个渠道；如果目标是“在用户已有的 IM 里触达”，渠道层还需要持续扩展。

## P3 Agent 能力与生态

### 1. 工具面窄

内置工具是文件读写、搜索、Shell、日期、Cron 共 9 个（[README.md:491-505](../../README.md#L491-L505)）；没有联网搜索/抓取、浏览器、MCP、PDF/Word/Excel/PPT 解析、图像/语音、代码沙箱。很多任务只能退化为“让模型写 Shell 命令”，既不方便也不安全。

对比：OpenClaw 有插件 SDK 与 ClawHub；QwenPaw 有 Skills/Plugins/MCP/市场，以及 browser-use、computer-use；nanobot 有 MCP、web search、image generation、多 Agent。

### 2. 记忆只有“会话 + 截断”

`AutoContextMemory` 的参数硬编码为 50 条消息、64k token、保留 20 条（[AgentRunner.java:80-84](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L80-L84)）；会话用 `JsonSession` 按 session 存 JSON。没有长期记忆、用户画像、跨会话召回、RAG/知识库、记忆编辑/清理。对比：QwenPaw 有三层记忆 + ReMe 知识库，nanobot 有 Dream 长期记忆。

### 3. 子 Agent 能力有限

- `CustomerAgentConfig.tools`（[CustomerAgentConfig.java:17](../../src/main/java/com/miniclaw/config/CustomerAgentConfig.java#L17)）虽然可配置，但 [AgentUtil.java](../../src/main/java/com/miniclaw/agent/AgentUtil.java) 没有读取它，子 Agent 实际拿到的是全部基础工具。
- 子 Agent 使用 `InMemoryMemory`（[AgentUtil.java:45](../../src/main/java/com/miniclaw/agent/AgentUtil.java#L45)），不持久化。
- 没有并行、递归深度、工具权限或调用配额控制。
- `skillPathList != null || !skillPathList.isEmpty()`（[AgentUtil.java:31](../../src/main/java/com/miniclaw/agent/AgentUtil.java#L31)）在 `skillPath` 为 null 时会 NPE；带自定义 Agent 又没配 `skillPath` 时，启动阶段就会失败。

### 4. 模型支持单一

只支持 OpenAI/Anthropic 兼容接口，`ConfigLoader` 里是全局单例缓存（[ConfigLoader.java:74-107](../../src/main/java/com/miniclaw/config/ConfigLoader.java#L74-L107)）；没有 fallback、路由、按 Agent 选模型、本地模型管理、token 成本核算或流式输出。

### 5. Skills 与 Prompt

Skills 从文件系统加载，每个请求都会重新注册（[AgentRunner.java:108-112](../../src/main/java/com/miniclaw/runner/AgentRunner.java#L108-L112)）；`SKILLMAP` 是静态 `HashMap`，没有并发保护（[SkillManager.java:22](../../src/main/java/com/miniclaw/skill/SkillManager.java#L22)）；任一路径没有 skill 就整体返回 null（[SkillManager.java:67-70](../../src/main/java/com/miniclaw/skill/SkillManager.java#L67-L70)）。没有注册表、版本、权限或扫描机制。

Prompt 偏 coding agent（[PromptManager.java:12-35](../../src/main/java/com/miniclaw/agent/PromptManager.java#L12-L35)），没有渠道、用户、时间等上下文，也没有安全边界提示。

## P4 工程化与运维

- 没有测试目录、没有 CI（无 `.github/`）、没有 Dockerfile、没有 `LICENSE` 文件（README 里引用了 `LICENSE`）；Java 25 + preview 编译，部署环境要求较高，仓库也没有 Maven Wrapper。
- 没有 metrics/tracing/audit，没有 token、成本、延迟指标；日志只输出到 console，且包含完整 prompt。
- 没有速率限制、多租户、RBAC；Web 无鉴权，飞书只有 `allowFrom`。
- 没有优雅停机/健康检查；飞书 `stop()` 未真正断开，调度 `shutdown()` 空实现；配置固定在 `~/.mini-claw/config.json`，无热加载。
- 依赖方面，fastjson 1.2.78 较旧（[pom.xml:91](../../pom.xml#L91)），Jackson/Gson/Fastjson 混用，没有依赖扫描。

## 如果只补三件事

1. **安全边界**：默认拒绝 + Shell/文件沙箱或人工审批；Web 加 token/登录；校验 sessionId 路径。
2. **并发与故障隔离**：按 session 串行、全局有界并发；单请求 try/catch + 超时 + 错误回复；有界队列。
3. **飞书体验**：流式/进度、Markdown/卡片、图片/文件、长文本分片；顺带修 @、`receive_id_type`、去重。

之后按目标选择：长期记忆/RAG、MCP/联网/浏览器、定时任务持久化、CI/Docker。

## 附：定位差异

mini-claw 约 4000 行，目标是学习 agentscope-java 与 Agent 架构（[项目学习指南](2.项目学习指南.md)）；OpenClaw/QwenPaw/nanobot 是数万到数十万 star、持续发版的成熟项目。功能数量上的差距是正常的，不必追求全面对齐；更有价值的是选定一个场景（例如“飞书里的个人助理”），把该场景的安全、体验和可靠性做深。

> README 也明确写了“该项目未进行生产级的测试，仅用于学习和研究目的”（[README.md:581](../../README.md#L581)）。上面的优先级建议是“如果要走向可用”，不是要求改变项目定位。
