# mini-claw 项目学习指南

## 一、项目简介

**mini-claw** 是一个精简版的 AI Agent 运行平台,参考了 OpenClaw、Nanobot、CoPaw 等项目的设计理念，是一个精简、迷你版的OpenClaw。项目基于 [agentscope-java](https://github.com/alibaba/agentscope-java) 框架构建,总代码约 4000 行,核心代码约 1000 行,非常适合作为学习 AI Agent 的入门项目。在学习之前强烈建议看一下 [1.Agent基本概念.md](1.Agent%E5%9F%BA%E6%9C%AC%E6%A6%82%E5%BF%B5.md)。

**适合人群:**

- 想要了解 OpenClaw 等项目的核心原理,但不知从何入手
- 需要学习如何基于 agentscope-java 开发 Agent 应用
- 希望快速理解 AI Agent 应用的架构设计和关键模块

### 核心特性

| 特性 | 说明 |
|:-----|:-----|
| **多渠道支持** | 标准输入输出、Web API(HTTP + SSE)、飞书机器人,一键切换 |
| **工具调用** | 内置文件读写、搜索、Shell 执行、日期工具,支持自定义 Skill 扩展 |
| **定时任务** | 支持周期任务、Cron 表达式、一次性延迟任务,基于 Quartz 调度器 |
| **会话持久化** | 基于 JsonSession 的会话存储与恢复,支持断点续聊 |
| **多模型支持** | 支持 OpenAI、Anthropic 等主流 LLM 模型,配置灵活 |

## 三、整体架构设计

### 架构概览

mini-claw 采用分层架构设计,从上到下分为:

```
┌─────────────────────────────────────────────────────────┐
│                      用户层                              │
│       CLI(命令行) | Web前端 | 飞书客户端                   │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                    渠道层 (Channel)                      │
│   StdChannel | WebChannel(HTTP+SSE) | FeishuChannel    │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                      核心层                             │
│         AgentMessageQueue | ChannelManager             │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                     Agent 层                            │
│  AgentRunner | ReActAgent | Memory | JsonSession       │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                   工具层 (Toolkit)                       │
│  FileIO | FileSearch | Shell | Date | Cron            │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                     模型层                              │
│            OpenAI API | Anthropic API                  │
└─────────────────────────────────────────────────────────┘
```

### 核心模块详解

#### 1. 渠道层 (Channel Layer)

**职责**: 统一不同接入方式的消息处理流程

渠道层是 mini-claw 的入口,负责将不同来源的消息统一转换为 Agent 可以处理的标准格式。

```java
// 渠道基类
public abstract class BaseChannel {
    protected ChannelType channelType;
    protected AgentMessageQueue agentMessageQueue;
    
    // 处理消息的统一入口
    public void process(String userId, String sessionId, String text);
    
    // 权限校验
    public boolean isAllowed(String userId);
    
    // 发送响应
    public abstract void send(AgentResponse response);
}
```

**三种渠道实现**:

| 渠道 | 说明 | 使用场景 |
|:-----|:-----|:---------|
| **StdChannel** | 标准输入输出,最简单的命令行交互 | 本地开发、调试测试 |
| **WebChannel** | HTTP REST API + SSE 推送 | Web 应用、移动端集成 |
| **FeishuChannel** | 飞书机器人,支持私聊和群聊@ | 企业内部工具、即时通讯 |

#### 2. 核心层 (Core Layer)

**职责**: 消息队列管理和渠道编排

核心层包含两个关键组件:

- **AgentMessageQueue**: 消息队列,负责接收来自各渠道的请求,并按顺序分发给 AgentRunner 处理
- **ChannelManager**: 渠道管理器,负责启动和停止所有渠道,并维护渠道与消息队列的关系

```java
// 消息流向
User → Channel → AgentMessageQueue → AgentRunner → Agent
                                                    ↓
User ← Channel ← AgentMessageQueue ← AgentRunner ← Agent
```

#### 3. Agent 层 (Agent Layer)

**职责**: Agent 的运行、推理和会话管理

Agent 层是核心业务逻辑层,包含:

- **AgentRunner**: Agent 运行器,从消息队列中取出请求,创建或恢复 Agent 实例
- **ReActAgent**: 推理执行 Agent,基于 ReAct (Reasoning + Acting) 模式进行迭代推理
- **AutoContextMemory**: 自动上下文记忆,管理对话历史
- **JsonSession**: 会话持久化,将会话状态保存到 JSON 文件

**运行流程**:

```
1. AgentRunner 从队列取出请求
2. 加载对应会话的 JsonSession(如果存在)
3. 创建或恢复 Agent 实例
4. Agent 进行推理-执行循环:
   a. 调用 LLM 模型生成响应
   b. 如果需要工具调用,执行工具并继续推理
   c. 直到生成最终答案
5. 保存会话状态
6. 将响应返回给渠道
```

#### 4. 工具层 (Tool Layer)

**职责**: 提供各种能力扩展

工具层提供了一系列内置工具,Agent 可以通过工具调用来完成特定任务:

| 工具类 | 功能 | 包含的工具 |
|:------|:-----|:----------|
| **FileIOTools** | 文件操作 | readFile, writeFile, editFile, appendFile |
| **FileSearchTools** | 文件搜索 | searchFiles, listFiles |
| **ShellTools** | 命令执行 | executeShell |
| **DateTools** | 日期时间 | currentDate |
| **CronTools** | 定时任务 | every, cron, at, delay, cancel |

#### 5. 调度层 (Scheduler Layer)

**职责**: 定时任务管理

调度层基于 Quartz 实现,支持:

- **周期任务**: 固定周期执行(如每 5 分钟)
- **Cron 任务**: 使用 Cron 表达式定义执行时间
- **一次性任务**: 指定时间或延迟执行

```java
// 定时任务示例
// 每 10 秒执行一次
every_seconds(10, "检查系统状态")

// 使用 Cron 表达式(每天 9:00)
cron_expr("0 0 9 * * ?", "发送每日报告")

// 5 分钟后执行一次
delay_seconds(300, "提醒我开会")
```

#### 6. 模型层 (Model Layer)

**职责**: 与 LLM 模型交互

模型层封装了与不同 LLM 提供商的交互逻辑,支持:

- **OpenAI API**: GPT-4, GPT-4o, GPT-3.5-turbo 等
- **Anthropic API**: Claude 3.5 Sonnet, Claude 3 Opus 等
- **OpenAI 兼容 API**: 支持其他兼容 OpenAI 接口的服务

## 四、消息处理流程

### 完整的消息流转过程

```
┌──────────┐
│   用户    │
└────┬─────┘
     │ 1. 发送消息
     ↓
┌──────────────────┐
│    Channel       │ ← 2. 权限校验(allowFrom)
│  (渠道层)         │
└────┬─────────────┘
     │ 3. 创建 AgentRequest
     ↓
┌──────────────────┐
│ AgentMessageQueue│ ← 4. 放入消息队列
│    (消息队列)     │
└────┬─────────────┘
     │ 5. takeRequest()
     ↓
┌──────────────────┐
│  AgentRunner     │ ← 6. 加载会话 JsonSession
│   (运行器)        │ ← 7. 创建/恢复 Agent
└────┬─────────────┘
     │
     ↓
┌──────────────────┐
│   ReActAgent     │ ← 8. 推理-执行循环
│   (Agent)        │
└────┬─────────────┘
     │ 9. 调用 LLM 模型
     ↓
┌──────────────────┐
│   Model (LLM)    │ ← 10. 返回响应(可能包含工具调用)
│   (模型层)        │
└────┬─────────────┘
     │ 11. 如果需要工具调用
     ↓
┌──────────────────┐
│   Tools/Skills   │ ← 12. 执行工具
│   (工具层)        │
└────┬─────────────┘
     │ 13. 工具结果返回 Agent
     ↓
┌──────────────────┐
│   ReActAgent     │ ← 14. 继续推理(循环步骤 8-13)
└────┬─────────────┘
     │ 15. 最终响应
     ↓
┌──────────────────┐
│  AgentRunner     │ ← 16. 保存会话
└────┬─────────────┘
     │ 17. 返回 AgentResponse
     ↓
┌──────────────────┐
│ AgentMessageQueue│ ← 18. 响应放回队列
└────┬─────────────┘
     │ 19. 分发给对应渠道
     ↓
┌──────────────────┐
│    Channel       │ ← 20. 发送给用户
└────┬─────────────┘
     ↓
┌──────────┐
│   用户    │
└──────────┘
```

### 会话持久化机制

mini-claw 使用 JsonSession 实现会话的持久化:

1. **会话隔离**: 每个用户+会话有独立的上下文
2. **自动保存**: Agent 每次响应后自动保存会话状态
3. **断点续聊**: 用户下次发起消息时,自动加载历史会话
4. **跨渠道共享**: 同一会话在不同渠道间共享状态

## 六、关键技术点

### 1. 渠道扩展机制

mini-claw 提供了灵活的渠道扩展机制,添加新渠道只需:

```java
// 1. 继承 BaseChannel
public class MyChannel extends BaseChannel {
    
    // 2. 实现启动逻辑
    @Override
    public void start() {
        // 初始化渠道
    }
    
    // 3. 实现停止逻辑
    @Override
    public void stop() {
        // 清理资源
    }
    
    // 4. 实现消息发送逻辑
    @Override
    public void send(AgentResponse response) {
        // 发送响应给用户
    }
}

// 5. 添加配置类
public class MyChannelConfig extends BaseChannelConfig {
    // 渠道特有配置
}
```

### 2. 工具注册机制

工具通过 ToolManager 统一管理:

```java
// 注册工具
toolManager.registerTool(tool);

// Agent 可以通过工具名称调用
toolManager.executeTool(toolName, arguments);
```

### 3. 定时任务调度

基于 Quartz 实现,支持多种触发方式:

```java
// 周期性任务(每 10 秒)
schedulerService.scheduleEvery(10, TimeUnit.SECONDS, task);

// Cron 表达式(每天 9:00)
schedulerService.scheduleCron("0 0 9 * * ?", task);

// 延迟任务(5 分钟后)
schedulerService.scheduleDelay(5, TimeUnit.MINUTES, task);
```

## 七、学习建议

### 学习路径推荐

1. **第一阶段: 理解概念，可阅读**
   - 了解 Agent 的基本概念，可参考 [Agent 框架文档](./docs/Agent框架文档.md)
   - 熟悉 agentscope-java 框架
   
2. **第二阶段: 运行项目**
   - 配置开发环境(Java 25+, Maven)
   - 配置 config.json 文件
   - 运行 StdChannel 体验基本功能
   - 尝试 WebChannel 和飞书渠道

3. **第三阶段: 阅读核心代码**
   - **入门**: `Main.java` → `ConfigLoader.java` → `AgentRunner.java`
   - **进阶**: `BaseChannel.java` → `AgentMessageQueue.java` → 各渠道实现
   - **深入**: `tool/` 目录 → `cron/` 目录 → `skill/` 目录

4. **第四阶段: 实践扩展**
   - 添加自定义工具
   - 扩展新的渠道
   - 实现 Skill 扩展
   - 自定义 Agent

### 关键文件推荐阅读顺序

```
1. Main.java (入口)
   ↓
2. ConfigLoader.java, Config.java (配置加载)
   ↓
3. ChannelManager.java (渠道管理)
   ↓
4. BaseChannel.java, StdChannel.java (渠道基类和简单实现)
   ↓
5. AgentMessageQueue.java (消息队列)
   ↓
6. AgentRunner.java (Agent 运行器)
   ↓
7. tool/*/ (工具实现)
   ↓
8. cron/schedule/SchedulerService.java (调度服务)
```
