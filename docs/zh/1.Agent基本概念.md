# Agent 基本概念（一看就懂版）

## 一、什么是 AI Agent？

**AI Agent 就是 "给了目标就能自己想办法完成任务的数字员工"**。

### 普通大模型 LLM vs AI Agent

很多人认为 LLM 和 AI Agent 是一回事，但其实它们有很大的区别。
- LLM：你问什么，它答什么，只会说不会做 
- Agent：只需要告诉它最终目标，它能自主规划并执行

---

## 二、什么是 ReAct Agent？

ReAct Agent 是 AI Agent 最常用的一种 "思考方式"，让 AI 学会 **"边想边做"**。

### ReAct 名字的由来

**ReAct = Reasoning（推理）+ Acting（行动）**

### ReAct Agent 的核心：TAO 循环

ReAct Agent 的工作流程可以用三个字母来记忆：**TAO 循环**

```
┌─────────────────────────────────────────┐
│                                         │
│   T = Thought（思考）                    │
│   智能体的"内心独白"，AI 先想清楚        │
│   "我现在要做什么？为什么要这么做？"      │
│                                         │
│              ↓                          │
│                                         │
│   A = Action（行动）                     │
│   根据思考结果，调用合适的工具去执行      │
│                                         │
│              ↓                          │
│                                         │
│   O = Observation（观察）               │
│   看看工具返回了什么结果，得到了什么新信息 │
│                                         │
│              ↓                          │
│        循环继续...                       │
└─────────────────────────────────────────┘
```

简单来说，就是一个 **"思考 + 调用工具"** 的循环，直到任务完成。

## 三、工具（Tools）

**Tool 是一个非常重要的概念！**

LLM 本身只能生成文本，无法执行实际操作。Tool 让智能体能够：
- 查询数据库
- 调用 API
- 执行计算
- 其他实际操作

### Tools 字段解析

从上述请求内容可以看出，`tools` 字段定义了工具列表。每个工具包含：

| 字段 | 说明 |
|------|------|
| `name` | 工具名称 |
| `description` | 工具描述，告诉 LLM 这个工具的用途 |
| `input_schema` | 输入参数的 JSON Schema 定义 |

示例中定义了三个工具（实际上只有getCurrentTime是我定义的，剩下两个下面讲解）：
1. **getCurrentTime**：获取当前时间
2. **lark cli agent**：飞书办公助手
3. **load_skill_through_path**：加载技能

## 四、Memory：记忆

由于大模型是 **无状态设计**，简单来说 LLM 只能根据你发给它的输入生成输出，无法记住你之前对话的内容。

### Memory 的作用

Memory 就是用来存储对话历史的。

以 AgentScope 中的 `io.agentscope.core.memory.InMemoryMemory` 为例：

```java
private final List<Msg> messages = new CopyOnWriteArrayList<>();
```

AgentScope 使用 `List` 来存储对话历史，每个对话历史是一个 `Msg` 对象，对应抓包内容的 `messages`。

---

## 五、Session：会话

### Session 的作用

Session 用于管理多个独立的对话会话。

以 `io.agentscope.core.session.InMemorySession` 为例：

```java
private final Map<String, SessionData> sessions = new ConcurrentHashMap<>();
```

Memory 的数据最终存在 `SessionData` 中，通过 `session_id` 区分不同的会话。

## 六、Skill：技能

### Skill 的本质

2025 年底 Skill 大火，很多人认为 Skill 无所不能，什么事情都写个 Skill 一了百了。

**那 Skill 的本质到底是什么？**

简单来说：**Skill = 提示词 + 脚本**。

### Skill 的渐进式加载

Skill 不是一次性全部加载给大模型的，而是 **按需加载**——先告诉大模型"你有哪些技能可以用"，等大模型判断需要时再加载详细内容。

这样做的好处：
- **节省 Token**：不需要把所有技能的完整内容都塞进上下文
- **按需激活**：大模型根据任务自主判断需要哪个技能

还是从最直观的抓包来看 Skill 是如何渐进式加载的。在 **"Agent 发送给 LLM 的内容示例"** 中有完整的抓包请求，其中 `system` 字段翻译为中文大概是：

```markdown
你是一个助手

## 可用技能

<usage>
技能提供专业能力和领域知识。当它们与你当前任务匹配时使用。

如何使用技能：
- 加载技能：load_skill_through_path(skillId="<skill-id>", path="SKILL.md")
- 技能将被激活，其文档将被加载并包含详细说明
- 可以使用相同工具通过不同路径加载额外资源（脚本、资源文件、参考资料）

路径信息：
当你加载一个技能时，响应将包含：
- 所有技能资源的精确路径
- 访问技能文件的代码示例
- 该技能特有的使用说明

模板字段说明：
- <name>：技能的显示名称
- <description>：何时以及如何使用此技能
- <skill-id>：load_skill_through_path 工具使用的唯一标识符
</usage>

<available_skills>

<skill>
<name>mysql-table-design</name>
<description>MySQL表设计规范。设计数据库表结构时使用此技能，包括：创建新表、审查表设计、检查现有表是否符合规范。触发场景：要求设计表、创建表、审查表结构、检查表命名或字段定义等。</description>
<skill-id>mysql-table-design_filesystem-workspace-5_skills</skill-id>
</skill>

</available_skills>
```

### 这段内容做了什么？

拆解来看，它做了三件事：

| 作用 | 说明 |
|------|------|
| 告诉大模型"你有一个工具箱" | 通过 `<available_skills>` 列出所有可用技能的名称和简介 |
| 手把手教大模型"怎么打开工具箱" | 给出精确的工具调用格式：`load_skill_through_path(skillId="xxx", path="SKILL.md")` |
| 明确告诉大模型"什么时候该用哪个工具" | 每个技能都有 `<description>` 描述触发场景，建立可扩展的技能体系 |

同时，`tools` 字段定义了 `load_skill_through_path` 工具，用于实际加载技能内容。

### Skill 加载流程总结

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│   1. Agent 在 system 中列出可用技能的摘要信息          │
│      （技能名称 + 简短描述）                           │
│                                                      │
│                      ↓                               │
│                                                      │
│   2. LLM 判断当前任务需要某个技能                      │
│      （Thought: "这个任务需要设计 MySQL 表..."）       │
│                                                      │
│                      ↓                               │
│                                                      │
│   3. LLM 调用 load_skill_through_path 工具            │
│      （Action: 加载 mysql-table-design 技能）         │
│                                                      │
│                      ↓                               │
│                                                      │
│   4. Agent 返回技能的完整内容（提示词 + 脚本）         │
│      （Observation: 获得详细的 MySQL 表设计规范）      │
│                                                      │
│                      ↓                               │
│                                                      │
│   5. LLM 基于技能内容继续执行任务                     │
│      TAO 循环继续...                                  │
│                                                      │
└──────────────────────────────────────────────────────┘
```

## 七、SubAgent：子智能体

### 什么时候需要 SubAgent？

当功能远超单个 Agent 上下文窗口承载能力的场景，就需要通过多个 Agent 来分工协作。

### SubAgent 的表现形式

在抓包的请求中，**SubAgent 和普通的 Tool 看起来一模一样**——它们都被定义在 `tools` 字段中，LLM 并不知道自己调用的是一个独立 Agent。

以 `lark cli agent` 为例：

```json
{
  "input_schema": {
    "type": "object",
    "properties": {
      "session_id": {
        "description": "Session ID for multi-turn dialogue. Omit to start a NEW session. To CONTINUE an existing session and retain memory, you MUST extract the session_id from the previous response and pass it here.",
        "type": "string"
      },
      "message": {
        "description": "Message to send to the agent",
        "type": "string"
      }
    },
    "required": ["message"]
  },
  "name": "lark cli agent",
  "description": "你是一个专业的飞书办公助手，拥有通过官方 lark-cli 工具直接操作飞书平台的能力。你可以理解用户的自然语言指令，自动调用合适的飞书 CLI 命令完成任务，并以清晰易懂的方式返回结果。"
}
```

### SubAgent vs 普通 Tool 的区别

| 对比维度 | 普通 Tool | SubAgent |
|---------|-----------|----------|
| 本质 | 一个具体函数/接口 | 一个独立的智能体 |
| 处理逻辑 | 固定逻辑，输入→输出 | 有自己的 LLM 调用，能自主思考和行动 |
| 会话管理 | 无状态 | 通常有 `session_id`，支持多轮对话 |
| 上下文 | 共享主 Agent 的上下文 | 拥有独立的上下文窗口 |
| 适合场景 | 简单明确的操作（写文件、查时间） | 复杂的多步骤任务（飞书办公助手） |

**核心区别**：SubAgent 内部有自己的 TAO 循环，它能自主规划并执行子任务，而普通 Tool 只是执行一个固定的操作。
